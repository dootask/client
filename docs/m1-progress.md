- Web：登录后全量同步 1000 个会话进 IndexedDB，另一个账号发消息后会话的未读和最后消息即时更新，控制台无报错

- 数据层还没有界面，iOS 跟 N2 一起看
- 实现上和旧前端的差别见 m1-features「N1 实现说明」

## N2 会话列表

- Web（Playwright）：窄屏、中屏、宽屏三种布局和深色模式；右键菜单的置顶 / 取消置顶、颜色（试完已改回）；本地 + 远程搜索、点联系人开单聊；已在「消息」Tab 时再点跳到下一个未读；窄屏进会话隐藏底部 Tab；1000 个会话滚动时只渲染约 30 行。截图 `tests/playwright-results/n2-*.png`
- Android 模拟器：列表内容（待办 / @ 标签、未读角标、已读勾、机器人标识、置顶底色）、Tab 角标浮在图标上；长按弹出系统菜单，标记已读 / 未读、免打扰开关（系统群置灰）、不显示该会话（系统确认框）都实际操作过，Tab 角标随之更新；搜索按拼音命中；进会话隐藏底部 Tab，返回后搜索词还在；再点「消息」Tab 跳到下一个未读并高亮。截图 `n2-android-*.png`
- 发现并修复：
  - Web 上 unistyles 的样式不作用到它不接管的组件（expo-image 的 `Image`、expo-router 的 `TabSlot`），头像宽高变成 0、`TabSlot` 不收缩导致整页 14000 多像素高、列表失去虚拟化。这两处改用行内样式 / RN StyleSheet
  - FlashList v2 默认开启的 `maintainVisibleContentPosition` 会把新置顶到第一行的会话挡在可视区上面，设 `autoscrollToTopThreshold` 解决
  - expo-router 的 `TabTrigger` 在当前 Tab 上再点会导航到带参数的路由，把打开的会话关掉；已聚焦时拦掉默认行为，只做「跳到下一个未读」
  - 安卓启动报 `Cannot find native module 'ExpoSQLite'`：expo-sqlite 58.0.15 的预编译 AAR 和 expo-modules-core 58.0.22 对不上。N1 新装的原生模块统一改成 `resources/app` 的版本（写死），坑记进 dev.md
  - 「不显示该会话」的系统确认框只有标题、正文空白：补上说明（隐藏后收到新消息会重新出现），确认按钮改为「不显示」
- 未做 / 差异：
  - 列表时间按设备时区显示，服务端时区换算没做（旧前端也没做）
  - 「隐藏 AI 入口」开关先按关闭处理，N7 接 AI 时补
  - L13 新建入口跟创建群组一起放到 N6
  - 「标注」分类只走服务端接口，不做本地缓存
  - 合并转发消息的摘要只显示「[转发]」，不带原会话标题

## N3 聊天窗口：列表与收发

- Web（Playwright）：群聊渲染（连组、头像、日期分隔、系统提示、语音 / 文件 / 引用 / 回应）；Enter 发送和「Enter 换行、Ctrl+Enter 发送」两种设置都试过；右键菜单的回复、回应、编辑（带「已编辑」标记）；表情面板插入；进会话定位到第一条未读并显示「以下为新消息」，停在历史时新消息只在回到底部按钮上计数；「@我」按钮跳到 @ 我的消息并高亮；`?msg=` 深链定位到旧消息居中；离开再进回到原来的滚动位置；宽屏三栏和深色模式。截图 `tests/playwright-results/n3-web-*.png`
- Android 模拟器：聊天页渲染、导航栏（人数、「连接中…」、其他会话未读）；键盘弹出时列表跟着上移；表情面板和键盘互相切换；发送、长按系统菜单、编辑（选了直接弹键盘）、返回后列表摘要更新；另一个账号连发 20 条后进会话定位到第一条未读。截图 `n3-android-*.png`
- 发现并修复：
  - 会话开着但停在历史位置时收到的新消息没算未读（R20 只靠已读上报清未读，没看到的不会上报）：关闭会话时，如果期间收到过新消息，先上报已读再向服务端取一次未读
  - 推送来的 @ 我的消息没进 `mention_ids`，「@我」按钮不出现：合并消息时一起记
  - 进会话还没定位完，列表先在底部渲染，把 @ 我的那条当成已看过，「@我」按钮随即消失：定位完成前不处理可见范围
  - Web 上只有右键菜单的文字气泡渲染成 `<button>`，里面再有按钮会嵌套报错：只有右键菜单、没有点击动作时不给按钮角色
  - Android 15 起短气泡可能多换一行被裁：带上 `plugins/with-text-bounds.js`
- 未做 / 差异：
  - 右滑回复、双击点赞、Web 悬停操作条随 N4
  - 图片、视频、文件点开先交给系统打开，画廊和文件预览随 N5
  - 长文「查看全文」没接，随 N5 的 G8
- iOS 真机包：`DooTaskdev-1.10.38-8942f21-chat-window-202611090209.ipa`（开发版，连 Metro），已放进下载页交给用户验证

## N4a 消息操作（长按 / 右键菜单）

N4 拆成两段：N4a 是长按 / 右键菜单里的全部操作，N4b 是输入区（D 组）。

- Web（Playwright）：右键菜单和悬停操作条；多选（Shift 点选）后逐条 / 合并转发；设待办（所有成员 / 指定成员 / 自己，带提醒时间）、待办条和「去完成」、待办详情里完成和改提醒；置顶条、点置顶条跳到原消息；标注、收藏和修改备注；翻译和选目标语言、隐藏翻译；已读名单；编辑、撤回；窄屏多选和转发。截图 `tests/playwright-results/n4a-*.png`
- Android 模拟器：长按浮起菜单（表情条 + 分组菜单），闲置后再长按也能马上弹出；多选（返回键退出）、选择文本页、设待办选指定成员、待办详情、取消待办（系统确认框）、转发选择页、翻译（结果显示在气泡里，长按译文出选语言）、收藏后提示里带「修改备注」、群聊点已读圈出已读名单。截图 `n4a-android-*.png`
- 发现并修复：
  - 安卓上 App 闲置几秒后长按消息，菜单要等松手才出来：长按状态放在聊天页上，弹菜单要重渲染整个聊天页，这次渲染被按住期间不断到来的触摸事件反复打断。菜单状态挪到单独的小组件里，长按只渲染菜单（坑记进 dev.md）
  - Web 悬停操作条在右键菜单、表情弹层关掉后一直挂着：React 合成事件把 portal 里的弹层算作这一行的子节点，收不到离开。改用原生 `mouseenter` / `mouseleave`
  - 推送里待办变了（R12）重拉会话待办，待办条即时更新
- 未做 / 差异：
  - 原生拖动连续勾选（C5 后半）、表情回应名单（B9）、快捷消息条（B7）随 N4b
  - 待办提醒时间按设备时区显示，服务端时区换算没做（同 N2）
  - 转文字（C2）菜单已接，语音消息的完整验证随 N4b 的按住说话一起做
