## N1 消息数据层

- 规则（R1–R20）和数据层单元测试 40 条；两个账号对测试服联调（`LIVE_EMAIL2` / `LIVE_PASSWORD2` 是收发消息的另一方）：同步列表、收推送、取消息、已读上报、发送队列全部通过
- Web：登录后全量同步 1000 个会话进 IndexedDB，另一个账号发消息后会话的未读和最后消息即时更新，控制台无报错
- Android 模拟器：同样 1000 个会话进 SQLite，推送即时更新
- 发现并修复：iPhone 开发包上并发写 SQLite 报「事务里再开事务」，缓存写操作改为排队；会话接口的 `last_at` 带微秒导致同一秒发的消息替换不了最后消息
- 数据层还没有界面，iOS 跟 N2 一起看
- 实现上和旧前端的差别见 m1-features「N1 实现说明」

## N2 会话列表

- Web（Playwright）：窄屏、中屏、宽屏三种布局和深色模式；右键菜单的置顶 / 取消置顶、颜色（试完已改回）；本地 + 远程搜索、点联系人开单聊；已在「消息」Tab 时再点跳到下一个未读；窄屏进会话隐藏底部 Tab；1000 个会话滚动时只渲染约 30 行。截图 `tests/playwright-results/n2-*.png`
- Android 模拟器：列表内容（待办 / @ 标签、未读角标、已读勾、机器人标识、置顶底色）、Tab 角标浮在图标上；长按弹出系统菜单，标记已读 / 未读、免打扰开关（系统群置灰）、不显示该会话（系统确认框）都实际操作过，Tab 角标随之更新；搜索按拼音命中；进会话隐藏底部 Tab，返回后搜索词还在；再点「消息」Tab 跳到下一个未读并高亮。截图 `n2-android-*.png`
- 发现并修复：
  - Web 上 unistyles 的样式不作用到它不接管的组件（expo-image 的 `Image`、expo-router 的 `TabSlot`），头像宽高变成 0、`TabSlot` 不收缩导致整页 14000 多像素高、列表失去虚拟化。这两处改用行内样式 / RN StyleSheet
  - FlashList v2 默认开启的 `maintainVisibleContentPosition` 会把新置顶到第一行的会话挡在可视区上面，设 `autoscrollToTopThreshold` 解决
  - expo-router 的 `TabTrigger` 在当前 Tab 上再点会导航到带参数的路由，把打开的会话关掉；已聚焦时拦掉默认行为，只做「跳到下一个未读」
  - 安卓启动报 `Cannot find native module 'ExpoSQLite'`：expo-sqlite 58.0.15 的预编译 AAR 和 expo-modules-core 58.0.22 对不上。N1 新装的原生模块统一改成 `resources/app` 的版本（写死），坑记进 dev.md
  - 「不显示该会话」的系统确认框只有标题、正文空白：补上说明（隐藏后收到新消息会重新出现），确认按钮改为「不显示」
- 未做 / 差异：
  - 列表时间按设备时区显示，服务端时区换算没做（旧前端也没做）
  - 「隐藏 AI 入口」开关先按关闭处理，N7 接 AI 时补
  - L13 新建入口跟创建群组一起放到 N6
  - 「标注」分类只走服务端接口，不做本地缓存
  - 合并转发消息的摘要只显示「[转发]」，不带原会话标题
  - 宽屏下跳到下一个未读落在当前打开的会话上时，高亮和选中同色，看不出闪烁
