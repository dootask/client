## N4b 第 1 块：发文件（D10、D11、D12、D16）

N4b 按功能分块提交，这一块是发文件：加号面板（最近照片、相册、拍摄、文件）、发送前预览、上传进度与失败重发，Web 上的拖进来、粘贴进来。

- Web（Playwright）：附件菜单选文件；图片、视频进预览（翻页、删除、加说明），其他文件直接发；拖进来的提示层和预览、粘贴图片后预览；上传进度、取消、失败后重发或删除；大文件的进度。截图 `tests/playwright-results/n4b-*.png`
- Android 模拟器：最近照片点选带序号，操作条（原图、预览、发送）；不勾原图时压缩（5.77 MB 的照片发出去 1440×1920、648 KB）；多张按选择顺序发出，说明跟在最后；上传进度圈，排队中的显示等待；预览翻页、缩略图、计数、带键盘输入说明、删到只剩一张；相册走系统选择器后进预览；文件直接发；拍摄先申请相机权限，拍完进预览再发。截图 `n4b-android-*.png`
- 发现并修复：
  - 一次发多张，小的先传完先发出，顺序乱了：上传完成即发出消息，所以同一会话一个一个传，不同会话之间仍最多同时传两个
  - Android 上发送预览底部被键盘盖住：unistyles 的 `ime` 在 Android 上已减去导航栏，iOS 上是键盘全高。加了 `bottomInset(bottom, ime)` 抹平平台差异，底部弹层（Sheet）一并改用。参数要直接传值，传 `rt.insets` 对象时 unistyles 识别不到依赖，键盘弹出后不更新
  - 从面板点「预览」发完回来，面板里还留着上次的勾选：交给预览时清掉
  - 面板操作条里「原图」和按钮没对齐：操作条高度改成触控高度
- 未做 / 差异：
  - 输入区其余部分（D7/D8 表情、D9 按住说话、D13 其余入口、D14 全屏编辑、D15 禁言提示条、D17 快捷键）以及 B7、B9、C5 后半、J6 在 N4b 后续块

## N4b 第 2 块：输入栏候选（D2、D3）

输入栏内容改成「纯文本 + mentions」（`sync/messenger/compose.ts`），草稿和发出的 HTML 与旧前端编辑器格式一致；内容放进会话页的 store，输入框和上方的候选浮层共用。光标前输入 @ # ~ % 弹出对应候选，/ 弹出快捷菜单（提及、任务、文件、工作报告，机器人会话行首再加机器人命令）。候选来源和分组同旧前端：@ 群内成员本地过滤（在线在前、机器人在后，多于 1 人时有「所有人」），群主或无主群再搜群外成员；# 项目任务、我的待完成、我协助的，输入关键词后加其他任务；~ 文件；% 我的汇报、收到的汇报。原生模块 `modules/mention-input` 照搬。

- Web（Playwright）：四种候选和 / 菜单；上下键、Enter、Tab 选择，Esc 收起；/ 选「任务」换成 # 候选；退格删到 mention 整段删除、光标位置正确；发出的 @ 和 # 服务端识别为链接；群里回复别人自动 @ 对方，取消回复时单独的 @ 去掉；编辑带 mention 的消息保留 mention，编辑完还原草稿。截图 `tests/playwright-results/n4b-d2-*.png`
- Android 模拟器：同上的候选、/ 菜单转任务候选；输入框里 mention 蓝色高亮，退格先删空格再整段删 mention；发出带 @ 和 # 的消息；长按别人的消息回复自动 @ 对方，关掉回复条后清空。截图在机柜 `~/qa/d2/`
- 设计：
  - Web 的输入框只能放纯文本，mention 不高亮，整段删除由 `applyTextChange` 回写文字并用受控 `selection` 放回光标；App 用分段子节点（mention 标成 `role="link"`），原生模块据此在同一次修改里删整段
  - 回复自动 @、编辑时收起草稿改在 layout effect 里做，不在渲染中改 store（store 改动会让别的组件重画）
- 未做 / 差异：
  - 任务群（group_type 为 task）的 # 没有「项目任务」分组：旧前端靠本地任务缓存找项目，这里只有项目群有
  - 选中任务、文件、报告后点消息里的链接跳转 ⏸ 到 M2

## N4b 第 3 块：发送方式（D5）

点按或 Enter 发送时按内容判断是否 Markdown（`looksLikeMarkdown`，特征和分量同旧前端，带 mention 的不算），是就以 `text_type=md` 发原文。发送按钮 App 上长按、Web 上右键弹出「无声发送 / MD 格式发送 / 普通格式发送」；编辑消息时没有这个菜单。

- Web（Playwright）：Markdown 自动识别（标题 + 列表按 MD 发，单个粗体分量不够按普通发）；右键菜单三项，无声发送带 `silence=yes`，MD 发送粗体渲染，普通发送 `##` 原样显示
- Android 模拟器：长按弹出系统菜单三项；无声、MD（粗体）发送正确；点按直接发、不弹菜单。截图在机柜 `~/qa/d5/`
- 设计 / 差异：
  - 无声发送按普通格式发、不做 Markdown 识别，同旧网页
  - `Menu` 加了 `hitSlop`（图标按钮的触摸区）和 `button`（右键菜单的触发元素本身是按钮，Web 上保留按钮角色）
