# M1 消息

> 目标：在新客户端里用上完整的即时通讯：会话列表、聊天、通讯录、推送点击直达、未读角标，iOS、Android、Web 四端一起做（桌面随 Web）。
> 进度和发现记在 `docs/m1-progress.md`；功能逐条的状态记在 `docs/m1-features.md`。规则同 M0：每项在 Web 和 Android 上通过才算完成，iOS 由用户真机验收；每项验收后提交并推送。

## 0. 现状和出发点

- **聊天窗口有现成的**：`resources/app` 的会话窗口 v2（`src/features/dialog/`、`packages/chat-ui/`，约 1.5 万行）已在安卓、iOS 真机验收，功能清单见它的 `docs/chat-rewrite/features.md`（约 110 项）。这份清单就是 M1 聊天窗口的底线，界面和交互照搬后按本项目规范改造
- **但它的数据全部来自旧网页**：原生页不直接请求接口，会话、消息、发送、草稿、表情、模板消息渲染都经壳协议向 WebView 里的 Vue store 取（`docs/chat-rewrite/bridge.md` 列了一百多个方法和事件）。这些在本项目里要重写成直连后端的数据层，是 M1 工作量最大的部分
- **App 里没有的**：会话列表、通讯录在 App 里一直是网页，要新做；聊天窗口的 Web 版要新做（倒序列表在网页上不可用，按 architecture.md 第 4 节参考 Happy Next 的 `column-reverse` 实现）
- **加密**：测试服关闭 `e2e_message` 开发。W6 新方案是传输层加密，只接在 API 的加密插件上，M1 不为它预留

## 1. 先做的事：功能清单

动手写代码前先建 `docs/m1-features.md`，之后按它汇报进度（先说还差什么）：

- 聊天窗口：以 App 的 `features.md` 为底，逐条标出在本项目里的做法（照搬 / 要改数据来源 / 要新做 Web 版 / 暂不做）
- 会话列表、通讯录、推送、角标：从 ai-kb（`messenger`、`mobile-notify`、`push-notice`、`desktop-notify`、`shortcut/messenger`）、`routes/api-map.md` 的 `dialog/*`、`users/*`、`push/device`，和旧前端 `messenger.vue`、`store/actions.js` 整理，每条注明来源
- 业务规则逐条对照旧代码核对（未读怎么算、哪些推送弹通知、免打扰和 @ 的关系、草稿等）

## 4. 不在 M1 范围内

- **跳到别的模块的入口**：打开任务、从消息新建任务、# 任务卡片的状态修改等落到 M2；打开项目落到 M3；在那之前点了显示占位屏
- **App 里「回到网页」的功能**：会议（发起、加入）、位置签到的地图选点、OKR、打开微应用。见第 5 节
- 靠近耳朵切听筒（要新原生依赖，App 里也没做）
- Electron 托盘未读、桌面通知快捷回复（M4 随 Electron 一起）
- ai-kb 同步（切换上线前不同步）

## 5. 已定（2026-11-08）

## 6. 工期估计

- 参照：App 的会话窗口 v2 从开工到 Android 验完约 7 天，那时数据由网页提供，只有原生端
- M1 要多做：数据层（N1）、会话列表、通讯录、Web 版聊天窗口、推送接入
- 估计 **3–4 周**，其中 N1 约 3 天、N3（两端列表）约 4 天、N4–N7 合计约 8 天、其余约 5 天。iOS 真机验收的轮次（App v2 当时有 5 轮）另算

## 7. 风险

| 风险 | 对策 |
| --- | --- |
| 数据层重写漏掉旧前端藏着的规则（未读、推送去重、消息合并） | N1 先写功能清单逐条核对 `store/actions.js`，vitest 覆盖；与旧前端同账号对照 |
| Web 版聊天列表（`column-reverse` + 虚拟列表）的滚动漂移 | 直接借用 Happy Next 已打磨过的模型和滚动控制，N3 单独验收 Web 的滚动、加载历史、跳转定位 |
| 模板消息、全屏编辑、表情数据原来靠网页提供 | 模板改为按块结构直接渲染；全屏编辑是第一个用到嵌入的地方（Quill），按 architecture.md 第 10 节实测白屏和内存，定下 WebView 预热做法 |
| 真实推送需要接了推送的包（开发包曾缺 Firebase 配置，点击直达只能模拟） | N9 用接了推送的包实测；安卓推送要的配置文件位置和用法先查 `resources/app` 的出包流程 |
| 工作量大、iOS 验收轮次多 | 每项单独验收提交；iOS 真机包按 N3、N6、N10 三个节点出，不每项都出 |
