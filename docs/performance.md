# 性能规范

> 2026-11-07 定。用户在 happy-app（`/home/coder/workspaces/happy-next/packages/happy-app`）上遇到的最大难点就是性能。下面的规则来自那里反复修过的问题，具体案例可以在 happy-next 仓库里用 `git log --grep=perf` 查看。

这些规则从第一行代码起就执行，不是事后优化。每个模块验收时都要过第 3 节的清单。

## 1. 硬规则

### 订阅与重渲染

1. **store 只订阅用到的字段**。用 selector 取最小值，不要订阅整个对象。
   - 反例：页面只需要会话列表里某个项目最近的机器和路径，却订阅了整个列表，结果任何一个会话更新都会让整页和弹层重渲染。
2. **推送进来的数据，没变就保持原引用**。只改了界面不显示的字段（心跳时间、元数据里没用到的部分）时，不替换对象，也不触发更新。
3. **高频推送要节流或合并**。心跳、在线状态、流式消息这类数据，按界面实际需要的精度更新。例如在线时间只在过期一分钟后才更新。
4. **列表行组件一律 memo**，只接收自己那一行需要的原始值。不要把每次都会重建的对象（整条元数据、主题对象）传给行。
5. **传给列表、输入框、导航选项的回调和参数必须稳定**（`useCallback` / `useMemo`，或者把逻辑下沉到子组件里自己订阅）。
   - 反例：会话页的导航栏选项每次渲染都是新对象，expo-router 会因此调用 `setOptions`，整个导航栈跟着重渲染。
6. **memo 的依赖不放 unistyles 的主题对象**（每次渲染都是新代理），只放用到的具体颜色值。
7. **输入时不能让列表重渲染**。输入框的状态留在输入框组件内部；列表、空状态、弹层拿到的回调要稳定。

### 动画

8. **Web 端没有原生动画驱动**，JS 动画每帧都会触发 React 渲染。Web 上的循环动画和状态动画用 CSS 或 `element.animate`，不用 Animated。
9. **Android 上，一直在跑的动画会让整个窗口每帧重绘**，即使用了原生驱动也一样。列表里避免常驻循环动画（呼吸点、流光等）；必须有时，在 Android 上降为有限几档的阶梯变化。
10. 动画过程中需要的尺寸和位置用 shared value 传，不用 state，否则动画每一帧都会让整个组件重渲染。

### 列表与键盘

11. **长列表一律用虚拟列表**（flash-list 或 App 现有的消息列表方案），`renderItem` 和 `keyExtractor` 保持稳定。
12. **跟随键盘的列表不要每帧滚动**。键盘移动时整体做位移，停下后再一次性滚到位置（happy-app 的做法）。
13. 在列表开头插入数据时会画面跳位，先看 `resources/app` 的 `patches/` 里已有的修复。

### 计算与数据

14. **贵的计算做缓存**：解析、解密、语法高亮、排序器、日期格式器这类，同样的输入只算一次，并限制缓存条数。
15. **大批数据分批处理**，不要一次阻塞主线程。例如解密每批几十条，长会话只处理还没处理过的部分。
16. **只把当前会话的消息放进内存**，其他会话的留在本地缓存里。

### 首屏与加载

17. **先画骨架，再填数据**。能用缓存或列表里已有数据画出来的立刻画，不允许只有一个转圈的白屏。
18. 路由页面和重型模块按需加载，冷启动只加载首屏用到的代码和语言包。
19. 嵌入的 WebView 要考虑复用和预热，原生页与 WebView 来回切换时不能白屏、不能重新加载。

## 2. 怎么测

| 端 | 工具 | 看什么 |
| --- | --- | --- |
| 全部 | React DevTools Profiler（含「Highlight updates」） | 一次操作重渲染了哪些组件、各多少次 |
| Web | Chrome Performance 面板 | 长任务、每帧脚本耗时、空闲时 CPU 是否归零 |
| Android | `adb shell dumpsys gfxinfo <包名>`、开发者选项里的 GPU 渲染条 | 掉帧、空闲时是否还在持续出帧 |
| 原生 | RN 自带的 Perf Monitor | JS 线程和 UI 线程帧率 |

性能问题以真机或模拟器实测为准，不凭读代码下结论。修复前后都留下数据。

## 3. 模块验收清单

每个模块完成时逐项过一遍，结果写进该模块的进度记录：

- [ ] 页面空闲时 CPU 归零：没有每帧还在跑的动画或定时器（Web 看 Performance，Android 看 gfxinfo）
- [ ] 在输入框里打字，列表不重渲染
- [ ] 收到一条与当前页无关的推送，当前页不重渲染
- [ ] 长列表（上千条）快速滑动不掉帧、不出现白块
- [ ] 打开页面先出骨架或缓存内容，没有只有转圈的白屏
- [ ] 弹出层（菜单、确认、提示）关闭状态下不渲染内容、不挂监听
- [ ] Web 端没有用 Animated 做循环或状态动画
- [ ] 中低端安卓模拟器上操作流畅
